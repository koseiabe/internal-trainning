= Ansible

== セクション１：コース概要
* IaC :サーバやネットワークの設定を設定ファイルに書き込んで自動化する手法


== セクション：IaC概要

=== IaC
* インフラ構築をコードを用いて行う方法

=== 手作業による課題
* 作業工数増大
* 作業品質低下 +
※クラウド上でのインフラ構築も例外ではない

=== コードによる作業内容と効果
* 定義ファイル作成やコマンド実行による作業内容軽減
* 作業工数の削減
* コードチェックにより設定ミス削減や作業品質向上

=== Iac ツール
|===
|IaC実現のためのツール
|Packer: コードはJson,HCL、マシン作成のイメージまで行う +

|Terraform: コードはHCL、マシンイメージを指定することでマシンイメージに沿った構築を行う +
 強み: インフラ構築、インフラメンテナンス、アプリケーション初期設定

|Ansible: コードはplaybookという単位にまとめられYAML形式の設定ファイルに記述し、設定ファイルをコマンド実行することでインフラ構築を行う +
 特徴: 設定ファイルにインフラの作成手順を記述する +
 #Terraformは作成手順を自動で設定してくれる点が違う +
 #※Ansibleはファイル内の処理を上から順番に実行するのみであるため、リソースの依存関係を意識する必要がある# +
 強み: インフラメンテナンス、アプリケーション初期設定、アプリケーションメンテナンス

|Puppet: オープンソースであり、コードはPuppet DSL、Terraform同様にインフラの最終状態を記述する +
 強み: Ansible同様にインフラメンテナンスに強い +
 弱み: 利用するためには構築対象のサーバにソフトウェアをインストールする必要があるため手間がかかる

|Chef: オープンソース、コードはRuby DSL、Ansible同様作成手順を記述する
 強み: インフラメンテナス、アプリケーション初期設定、アプリケーションメンテナンス
 弱み: Puppet同様にインストールが必要
|===
